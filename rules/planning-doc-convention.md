# Planning-Doc Convention Rule

> Planning docs are versioned single-source-of-truth artifacts, not draft notebooks (IMP-036). Always loaded.

## Scope

Any file at any level of the repo, subprojects included, named `PLANNING.md`, `PLAN.md`, `PLANS.md`, `ARCHITECTURE.md`, `ARCH.md`, `SPEC.md`, `SPECIFICATION.md`, `SPECS.md`, `DESIGN.md`, `DESIGNS.md`, or under `docs/plans/`, `docs/specs/`, `docs/architecture/`. Not covered: scratch docs that ARE explicitly drafts (BRAINSTORM.md, NOTES.md, TODO.md) and autogenerated docs (API references, schema dumps — their own update cadence).

## The Convention

**Planning docs are LIVE SPECS** — the current intended state of the system and the work being done, not scratch space for in-progress thinking. Frequent small amendments are healthy; this is not a ban on editing.

1. **Commit changes to a planning doc in dedicated commits**, never mixed with code edits — the history must let a reader follow how the plan evolved separately from the code.
2. **Don't refactor a planning doc in-place during code work.** If the plan turns out wrong, finish the immediate code change, then update the plan in a separate commit explaining what changed and why.
3. **Edits, not rewrites:** grow by amendment (clarification, new sections, struck-through obsolete sections); a full rewrite signals "this was a draft, not a spec."

## Anti-Pattern: Draft-Notebook Mode

Symptoms: 200+ edits in a single session; 80%+ of edits are rewrites (`old_string` empty or `Write` tool); file size oscillating by >20% within a session; the same section rewritten 3+ times in a day. The doc has become a thinking space, and the git history loses signal — 200 rewrites look the same as one thoughtful update from outside the session.

## Recommendation: Draft → Replace Workflow

When >50% of the content must change — the original stays a live spec while you get a scratch space:

```
1. Copy the original to PLANNING-draft-YYYY-MM-DD.md (or PLAN-draft-*.md)
2. Iterate in the draft file — any number of rewrites, no commit hygiene needed
3. When the draft is stable, replace the original in ONE final commit:
   - Commit message: "planning: rework X (draft → PLANNING.md)"
   - Body: summarize what changed structurally and why
4. Delete the draft file in the same commit, or in an immediate follow-up
```

## Session-End Warning

`session-end-check.sh` (Reminder 4) warns at the end of any session with ≥10 edits where ≥80% are rewrites, citing this rule. Treat it as a prompt to use draft → replace next time — social pressure, not a hard error, coverage gate, or pre-commit blocker.
